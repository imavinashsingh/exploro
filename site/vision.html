The agent we are building

Give it a goal. It finds the tests.

Exploro is becoming an autonomous exploratory QA engineer. It understands an application, invents relevant test scenarios, drives a real browser, investigates failures, and turns what it observed into verifiable evidence.

Evidence first. Never an invented result.

Not a script runner. An agent that thinks.

Every action starts from fresh evidence. The agent decides what is worth testing next instead of following a fixed checklist.

  1. Understand

    Intent and risk

  2. Explore

    UI, repository, context

  3. Hypothesize

    Generate scenarios

  4. Execute

    Real browser actions

  5. Observe

    DOM, network, console

  6. Verify

    Assertions and evidence

  7. Learn

    Useful memory

It loops back whenever the page changes, a check fails, or a new risk appears.

Six things the agent must do really well

Working with Exploro should feel like working with a thoughtful QA engineer, not programming a list of browser commands.

Invent the right tests

Turn a broad goal into positive, negative, boundary and exploratory checks, without the user writing every scenario.

Understand any interface

Read the DOM, accessibility tree and visual state: forms, sliders, tabs, dialogs, navigation and responsive layouts, never fixed selectors.

Use the whole toolkit

Correlate the page with console, network, screenshots, DevTools and repository context to find the cause, not just the symptom.

Recover intelligently

Handle popups, new tabs, stale elements, delays and unexpected screens by re-reading the live state.

Build trustworthy evidence

Capture what actually happened, and give every scenario an honest verdict:

PASSFAILBLOCKEDINCONCLUSIVESKIPPED

Remember what matters

Keep project knowledge, past defects, tested paths and recovery strategies, without treating old observations as unquestioned facts.

Keep the foundation. Build the intelligence.

One reasoning engine uses every available tool and source of context. No competing planner, no separate verification brain, no required local model.

Built on the Electron desktop app and T3 Code's agent infrastructure. Memory and code intelligence are modules on top, not replacements for the base. Memory works without Hindsight or Ollama; embeddings are pluggable, never the agent's core reasoning.

Intelligence without fragile magic

These guardrails matter more than the choice of model, framework or memory library.

No hardcoded sites or controls

Handle unfamiliar applications by inspecting them, never by assuming particular buttons, selectors or pages.

Observations decide the next action

When navigation, timing or layout differs, replan from live evidence instead of retrying the same failed action.

Never fabricate a verdict

Keep expectation and observation apart. A blocked test is not a failure, and a click is not proof of success.

The human controls risky steps

Ask before destructive, irreversible or sensitive actions. Keep the trace, reasoning and evidence reviewable.

Memory informs, never overrides

Recall what was learned before, then check it against the current page and code.

Model independence

Use the agent the user already has. No required Ollama, separate LLM, Hindsight service or local model.

Definition of success

Can it test an app it has never seen before?

Not just click through a demo: make reasonable decisions, react to unknown states, and explain what was proven. These are the acceptance criteria for the agent.

  • Creates meaningful tests from a high-level goal
  • Handles forms, sliders, tabs, links and several viewports
  • Uses DOM, DevTools, repository and memory when relevant
  • Recovers from unexpected browser behaviour
  • Produces honest, evidence-backed verdicts
  • Improves across sessions without becoming brittle
